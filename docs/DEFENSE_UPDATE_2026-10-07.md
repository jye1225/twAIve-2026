# twAIve 심사 이후 변경 사항과 평가 모델 설명

작성 기준: 2026-10-07 현재 구현. 교수님께 설명할 때 사용할 기술 설명 자료입니다.

## 1. 먼저 전달할 핵심

> 이전에는 제작자가 설정한 가감점으로 결과를 보여줬습니다. 현재는 대한민국 인공지능 윤리원칙을 평가 축으로 삼고, 선택 행동을 원칙별 0~4단계 루브릭에 연결해 수행률을 계산하도록 바꿨습니다. 선택의 이유, 원칙별 근거, 사전·사후 변화까지 확인할 수 있습니다. 다만 정부가 정한 공식 점수나 검증된 심리검사는 아니며, 수치화한 루브릭의 타당성은 추가 검증이 필요합니다.

K-means에 대해서는 다음처럼 구분해야 합니다.

> 현재 화면의 학습자 유형은 설명 가능한 규칙 기반 분류입니다. K-means는 동의한 학습 기록에서 비슷한 패턴을 탐색하기 위한 별도 오프라인 분석 코드로 구현했습니다. 웹 화면에 학습된 군집 모델이 연결되어 있는 상태는 아닙니다.

## 2. 비교 기준과 변경 내역

심사 때 정확히 어떤 파일을 실행했는지는 영상이나 당시 배포 기록까지 대조해야 확정할 수 있습니다. 여기서는 저장소에서 심사일 9/9 이전에 확인되는 최근 스냅샷인 `eb1d183`(9/8)의 `app.js`를 기준으로 비교했습니다. 기억에만 의존한 비교가 아닙니다.

## 3. 정책을 어떻게 사용했는가

### 주 평가 체계

현재 최상위 평가 축은 관계부처 합동 「대한민국 인공지능 윤리원칙」입니다. 공식 자료 등록일은 2026-08-21입니다. 3대 가치는 전체 지향점이고, 7대 원칙을 실제 평가 축으로 연결했습니다. 자료: [대한민국 정책브리핑 원문·첨부](https://www.korea.kr/archive/expDocView.do?docId=41882&pWise=sub&pWiseSub=J2).

3대 가치: 인간의 존엄성, 사회의 공공선, 인류의 지속가능성.

7대 원칙: 인간중심성, 프라이버시 보호, 공정성·포용성, 책임성, 안전성, 신뢰성, 투명성.

3대 가치에 따로 가중치를 매겨 합산하지 않습니다. 각 에피소드에서 관찰할 수 있는 관련 원칙만 평가합니다.

### 보완 자료

- 대학 AI 활용 윤리 가이드라인: 과제 에피소드의 AI 사용 공개, 검증, 작성 책임과 학문적 진실성을 검토하는 보완 자료입니다. 대학 상황의 권고를 중·고등학생에게 법적 의무처럼 적용한 것은 아닙니다. [한국대학교육협의회 공식 게시물](https://www.kcue.or.kr/notice/sub06.php?at=view&idx=658867).
- AI 기본법 관련 태그: 코드에 관련 법 조항 참고가 연결되어 있지만, 게임 선택으로 개인이나 사업자의 법 위반을 판정하지 않습니다. 법적 의무의 적용 주체와 교육용 행동 기준은 구분해야 합니다.
- KISDI 자율점검표: 일반 원칙을 공통 질문과 분야별 질문으로 구체화하는 설계 방법을 참고했습니다. 해당 페이지의 기존 10대 핵심요건 체계와 현재의 7대 원칙은 같은 목록이 아닙니다. KISDI의 Level 0·1·2도 수행 점수가 아니라 구체화 계층입니다. [KISDI 공식 자율점검표 설명](https://ai.kisdi.re.kr/aieth/main/contents.do?menuNo=400008).

### 원칙에서 점수까지의 연결

```text
외부 정책·교육 기준
→ 에피소드와 관련된 원칙 선택
→ 장면에서 관찰할 행동 정의
→ 선택지에 원칙별 0~4 수준 배정
→ 선택 기록에 수준·근거 저장
→ 원칙별 수행률과 개선 행동 제시
```

예를 들어 합성 이미지 사용 장면에서는 동의, 피해 예방, 후속 대응, AI 사용 공개 같은 행동을 구분합니다. 관련 원칙을 살폈는지와 실제로 어떤 행동을 했는지를 선택지별로 평가하도록 만든 것입니다.

**정책에서 직접 가져온 부분과 팀이 설계한 부분은 다릅니다.** 평가 축의 외부 근거는 정책이지만, 상황에 대한 해석, 선택지, 0~4 수준 배정, 평균 방식, 엔딩 경계는 팀의 설계입니다. 정책이 모든 선택지의 정답과 점수를 지정해 주지는 않습니다.

`KAI-2.3` 같은 표기는 코드에서 정책 근거를 추적하기 위해 붙인 내부 식별자입니다. 정부의 공식 인증 등급이나 별도 법 조문 번호가 아닙니다. 실제 원문 위치와의 대응표를 검토 자료로 함께 유지하는 것이 좋습니다.

## 4. 이전 점수 계산의 실제 방식

심사 전 `resetScores()`는 모든 지표에 50점을 주었습니다. `applyChoice()`는 선택지의 `delta`를 더하고, 결과를 0~100으로 제한했습니다. `scoreAverage()`는 확산·의존처럼 낮을수록 좋다고 정한 지표만 `100-값`으로 뒤집은 뒤 평균을 냈습니다.

예전 딥페이크 첫 장면에서 "같이 해본다"의 설정은 다음과 같았습니다.

```text
시작: 윤리 50, 관계 50, 확산 50
선택 가감점: 윤리 -8, 관계 +2, 확산 +8
선택 후: 윤리 42, 관계 52, 확산 58
종합: round((42 + 52 + (100-58)) / 3) = 45점
```

문제는 왜 윤리는 -8이고 확산은 +8인지 외부 근거와 연결되지 않았다는 점입니다. 관계·편의 같은 서사 지표와 윤리 수행 지표도 종합값 안에서 섞일 수 있었습니다.

## 5. 현재 점수 계산을 단계별로 설명

### 5.1 선택지의 원칙별 수행 수준

| 수준 | 화면 명칭 | 팀이 정한 교육용 해석 |
| --- | --- | --- |
| 0 | 위반 | 핵심 기준에 반하는 행동 또는 피해 확대 |
| 1 | 위험 | 위험을 무시하거나 책임을 회피 |
| 2 | 부분 충족 | 문제는 인식했지만 확인·실천이 부족 |
| 3 | 준수 | 기준을 확인하고 책임 있게 행동 |
| 4 | 적극 실천 | 예방·검증·공개·재발 방지까지 수행 |

한 선택이 모든 원칙에서 같은 수준을 갖지는 않습니다. 예를 들어 피해 대응은 잘하지만 공개가 부족한 선택이라면 책임성과 투명성이 다르게 평가될 수 있습니다.

### 5.2 원칙별 점수

```text
원칙 P의 점수 = round(해당 원칙의 수준 합계 / (평가 횟수 × 4) × 100)
```

관련 없는 장면은 그 원칙의 평가 횟수에 포함하지 않습니다. 기록이 없는 원칙은 0점이 아니라 `null`, 즉 미평가입니다. 버전 3의 유효한 0~4 정수 수준만 합산합니다.

### 5.3 실제 완료 경로 예시: 딥페이크 86점

| 장면에서 고른 행동 | 프라이버시 | 책임성 | 안전성 | 투명성 |
| --- | --- | --- | --- | --- |
| 위험하지 않냐고 말한다 | 3 | 3 | 3 | 미평가 |
| 지우라고 확실히 말한다 | 4 | 3 | 미평가 | 미평가 |
| 피해 학생에게 먼저 사과하고 필요한 도움을 묻는다 | 3 | 4 | 4 | 미평가 |
| AI 이미지 사용 전 동의 확인 규칙을 만든다 | 4 | 4 | 4 | 3 |

계산 결과:

- 프라이버시: `round(14 / 16 × 100) = 88점`
- 책임성: `round(14 / 16 × 100) = 88점`
- 안전성: `round(11 / 12 × 100) = 92점`
- 투명성: `round(3 / 4 × 100) = 75점`
- 에피소드: `round((88 + 88 + 92 + 75) / 4) = 86점`

원칙별 점수를 먼저 반올림하고, 그 값의 평균을 다시 반올림합니다. 모든 장면의 모든 수준을 한꺼번에 합산하는 방식과는 다릅니다. 에피소드 안에서는 평가된 원칙이 같은 비중을 가지며, 평가 횟수가 적은 원칙도 평균에서 같은 비중을 갖는 설계입니다.

### 5.4 에피소드 점수와 상단 점수는 무엇이 다른가

- 기록·리포트의 에피소드 점수: 그 에피소드에서 평가한 원칙들의 평균입니다.
- 상단 "AI 윤리 감수성": 완료한 에피소드의 저장 점수들을 평균한 값입니다. 모든 원칙 기록을 다시 합쳐 계산한 값은 아닙니다.
- 미완료 에피소드: 기록 탭에서 현재까지의 점수는 볼 수 있지만 상단 완료 평균에는 포함하지 않습니다.
- 기록 탭의 결과 버튼: 선택한 에피소드의 저장된 완료 기록을 복원합니다. 다시 플레이하거나 기록을 덮어쓰지 않습니다.

### 5.5 엔딩과 수행 구간

엔딩: 75점 이상 `Good End`, 50~74점 `Normal End`, 50점 미만 `Bad End`. 선택 기록이 없으면 진단 전입니다. 이 경계값은 정책의 공식 경계가 아니라 팀이 정한 피드백 구간입니다.

원칙별 수행 문구는 75점 이상 "안정적으로 실천", 50점 이상 "기준을 이해하는 중", 25점 이상 "추가 연습 필요", 그 미만 "우선 점검 필요"입니다.

### 5.6 점수에 넣지 않는 데이터

판단 이유와 응답 시간은 윤리 점수의 가감점에 넣지 않습니다. 오래 고민했다고 감점하거나 특정 이유를 골랐다고 자동 가산하지 않습니다. 사전·사후 응답 수준과 변화도 에피소드 수행 점수와 별도로 보여줍니다.

```text
사전·사후 변화 = 사후 응답 수준 - 사전 응답 수준
```

이 값은 학습 전후 반응 변화의 보조 지표입니다. 한 문항의 변화만으로 교육 효과나 인과관계를 입증한 것은 아닙니다.

### 5.7 검증 상태와 남아 있는 한계

자동 테스트는 22개 선택 장면, 61개 선택지, 7개 원칙 연결과 324개 종료 경로를 점검합니다. 이는 점수 범위·계산·루브릭 누락을 검증하는 것이며 교육적 타당도를 검증한 결과는 아닙니다.

다음 검증은 아직 별도로 필요합니다: 전문가의 문항·루브릭 검토, 독립 평가자 간 일치도, 3단계와 4단계 구분의 타당성, 동일 가중치와 엔딩 경계의 민감도, 실제 학습자 대상 사용성 및 학습 효과 평가. 현재 점수는 공인 척도나 성격 판정이 아닌 선택 행동에 대한 교육용 수행 지표로 설명해야 합니다.

## 6. 핵심 개념의 Point는 무엇인가

`learningText(episodeId)`에 미리 작성한 학습 요약 문장을 줄 단위로 나누고, 위에서부터 `Point 1`, `Point 2` 순서로 표시합니다. 현재 챗봇은 2개, 다른 에피소드는 3개입니다.

Point 번호는 중요도 순위, 정부 문서의 조항 번호, 개인 점수, K-means 결과가 아닙니다. AI가 실시간 생성하는 문장도 아닙니다. 에피소드에서 기억해야 할 내용을 팀이 요약한 고정 콘텐츠입니다. 정책 원문을 그대로 인용한 것으로 소개하지 않아야 합니다.

| 에피소드 | Point의 내용 흐름 | 연결해 설명할 원칙 |
| --- | --- | --- |
| 삭제되지 않은 얼굴 | 얼굴 사용 결정 → 합성물 피해 → 공유·방관 책임 | 프라이버시 보호, 안전성, 책임성 |
| 진실은 클릭 뒤에 있다 | AI 생성물의 사실감 → 주장과 검증 → 제보·정정 | 신뢰성, 투명성, 안전성, 책임성 |
| AI 챗봇과 마음의 거리 | 챗봇 도움의 한계 → 현실 도움 요청 | 인간중심성, 안전성, 신뢰성, 책임성 |
| AI가 써준 수행평가 | 보조 도구의 활용 → 작성·학습 책임 → 공개·검증 | 인간중심성, 책임성, 신뢰성, 투명성 |
| 추천 알고리즘이 아는 것 | 최소 권한 → 편향·배제 점검 → 데이터 통제 | 프라이버시 보호, 공정성·포용성, 투명성, 책임성 |

이 표의 연결은 앱의 콘텐츠와 평가 축을 설명한 것입니다. 각 요약 문장의 법적 정확성과 연령 적합성은 추가 검토 대상입니다. 화면의 출처 표시는 전체 학습 콘텐츠가 참고한 체계를 뜻하며, 모든 문장이 해당 정책의 직접 인용문이라는 뜻은 아닙니다.

## 7. 현재 웹의 분석 모델: K-means와 구분

선택 기록에서 특징을 뽑고 명시적인 규칙으로 유형을 분류합니다.

- 위험 선택 비율: 선택별 원칙 수준 평균을 반올림한 대표 수준이 0~1인 선택의 비율.
- 적극 실천 선택 비율: 대표 수준이 3~4인 선택의 비율. 현재 코드상 3단계 "준수"도 포함됩니다. 화면 명칭을 엄밀히 읽을 때 주의해야 합니다.
- 원칙 편차: 가장 높은 원칙 점수 - 가장 낮은 원칙 점수.
- 판단 이유: 권리, 검증, 후속 행동, 편의, 주변 관계, 불확실의 빈도.
- 응답 시간: 선택까지 걸린 시간의 평균. 점수가 아닌 행동 특성입니다.

분류 순서:

1. 분석할 기록이 없으면 분석 대기.
2. 위험 선택 비율이 40% 이상이면 위험 신호 점검형.
3. 전체 75점 이상, 위험 비율 25% 이하, 원칙 편차 35점 이하이면 균형 실천형.
4. 나머지는 가장 낮은 원칙에 따라 AI 의존·권리 보호·책임 행동·검증 보완 유형으로 연결.

조건이 겹치면 앞선 규칙이 우선합니다. 이는 군집 중심과의 거리로 분류하는 알고리즘이 아닙니다.

현재 "데이터 신뢰도" 역시 모델 정확도 확률이 아닙니다. 기록이 얼마나 충분한지 나타내는 내부 지표입니다.

```text
충분도 = round(
  min(선택 수 / 12, 1) × 50
  + 이유 기록 비율 × 25
  + 사전·사후 수준이 모두 있으면 15
  + 시도 횟수가 2회 이상이면 10
)
75 이상 높음 / 45 이상 보통 / 나머지 낮음
```

## 8. K-means 구현을 자세히 설명

### 8.1 목적과 현재 적용 상태

목적은 "누가 윤리적으로 좋은 사람인가"를 자동 판정하는 것이 아니라, 비슷한 선택 패턴을 가진 학습 기록을 묶고 집단별 보완 활동을 제안하는 것입니다. `ml/cluster_learners.py`에 별도 구현되어 있습니다.

현재 저장소에서 실제 데이터로 학습한 모델 산출물이나 웹에 연결한 추론 경로는 확인되지 않습니다. 따라서 "현재 사용자 유형은 K-means로 판정한다", "실제 학생 데이터로 정확도가 검증됐다"고 발표하면 안 됩니다. 이번 작업에서 실제 학생 데이터를 학습시키지도 않았습니다.

### 8.2 입력과 최소 실행 조건

현재 코드가 요구하는 수치형 특징은 11개입니다: 원칙 점수 7개, 평균 응답 시간, 사전·사후 변화, 위험 선택 비율, 적극 실천 선택 비율. 범주형 특징은 가장 많이 선택한 판단 이유 1개입니다. 동의 확인용 열도 필요합니다.

스크립트는 필수 열을 확인하고 `analytics_consent`가 true/1/yes인 행을 선별합니다. 동의한 행이 50개 미만이면 실행을 중단합니다. 50은 팀이 정한 파일럿 실행 제한이며 통계적 검정력 분석으로 정한 적정 표본 수가 아닙니다. 50행을 자동으로 50명의 독립 학습자로 볼 수도 없습니다.

익명화, 완료 여부, 평가 버전 통일, 합성 데이터 제외, 중복 학습자 처리, 응답 시간 이상치 검토는 입력 데이터 준비 단계에서 별도로 해야 합니다. 스크립트가 이 조건을 모두 자동 보장하지는 않습니다. 대시보드의 준비 기록 수 집계도 학습 모델을 실행하거나 학습 데이터 CSV를 자동 생성하는 기능은 아닙니다.

### 8.3 전처리

1. 수치형 결측값은 중앙값으로 대체합니다.
2. 수치형 특징은 `StandardScaler`로 표준화합니다: `z=(값-평균)/표준편차`.
3. 범주형 결측값은 최빈값으로 대체하고 판단 이유를 원-핫 인코딩합니다.

점수(0~100), 비율(0~1), 시간(초)을 그대로 거리 계산에 넣으면 단위 차이에 영향을 받기 때문에 표준화를 합니다. 결측 대체는 실제 미평가를 "관찰한 수행"으로 바꾸는 것이 아니라 군집 입력을 만들기 위한 가정입니다. 어느 원칙이 많이 비어 있는지 따로 점검해야 합니다.

### 8.4 군집 만들기와 k 선택

표준화된 각 행을 특징 벡터로 보고, 군집 내부의 중심과 데이터 사이 제곱 거리 합이 작아지도록 군집을 찾습니다. 목적식은 `Σ ||x_i - μ_(cluster_i)||²`입니다. 이것은 윤리 점수 계산식이 아닙니다. [scikit-learn KMeans 공식 설명](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.KMeans.html).

현재 코드는 k=2~5 후보마다 학습하고 평균 silhouette 점수를 비교해 가장 큰 후보를 선택합니다. 각 학습은 `n_init=20`, `random_state=42`를 사용합니다. 여러 초기 중심으로 시도하고 재현 가능한 결과를 얻기 위한 설정입니다.

Silhouette은 자기 군집 안 거리와 다른 군집까지의 거리를 비교합니다. `s=(b-a)/max(a,b)`, 범위는 -1~1입니다. 분리 정도를 보는 내부 평가이며 "윤리 정답률"이나 "학생 지도 정확도"가 아닙니다. [scikit-learn 군집 평가 설명](https://scikit-learn.org/stable/modules/clustering.html#silhouette-coefficient).

### 8.5 결과 해석과 출력

선택한 k로 다시 학습해 각 행에 군집 번호를 붙입니다. 군집별 원칙 점수 평균 중 가장 낮은 원칙을 찾고, 그 원칙에 대응하는 지도 활동 문구를 연결합니다. 번호 자체에는 우열이 없습니다. 다른 데이터나 실행에서는 군집 번호가 다른 의미를 가질 수 있습니다.

- `learner_clusters.csv`: 입력 행과 군집 번호. 동의 열만 제거하므로, 입력에 이름·아이디가 있으면 자동 익명화되지 않습니다.
- `cluster_summary.json`: 군집 크기, 취약 원칙과 평균, 위험 비율, 사전·사후 변화, 지도 활동.
- `learner_clusterer.joblib`: 전처리기, K-means 모델, 사용 특징 목록.

아직 필요한 검증은 실제 동의 표본 확보, 군집 안정성, k 후보의 타당성, 특징 가중치·이상치 영향, 군집 해석의 교육적 유용성입니다. 120명 합성 시연 데이터는 실제 연구 표본이나 모델 타당성의 증거로 사용하지 않습니다.

## 9. OpenAI·저장·분석의 역할 분리

브라우저는 학습 화면을 표시하고, Supabase는 인증·프로필·진행 기록을 저장합니다. Vercel 서버 API는 OpenAI 요청을 처리합니다. GitHub Pages도 해당 서버 API를 호출할 수 있도록 연결되어 있습니다. API 키를 브라우저 소스에 넣는 구조는 아닙니다.

AI는 선택 이유 문구와 결과 설명을 돕습니다. 원칙 수준과 점수 자체는 사전 정의한 루브릭과 계산 코드가 결정합니다. AI 요청이 실패하거나 지연되면 기본 이유 문구를 사용할 수 있습니다. 배포 설정과 실제 특정 계정의 응답 성공 여부는 구분해 확인해야 합니다.

현재 실제 학습자 유형 분류, OpenAI 자연어 설명, 오프라인 K-means는 서로 다른 역할입니다.

## 10. 교수님께 1분 설명

> 심사 때 점수 기준이 자체 판단이라는 지적을 받은 뒤, 외부 정책 근거를 추적할 수 있도록 평가 구조를 바꿨습니다. 이전에는 자체 지표가 50점에서 시작해 선택마다 가감됐지만, 지금은 국가 AI 윤리원칙을 기준으로 원칙별 선택 행동을 0~4단계로 평가합니다. 해당 원칙을 평가한 선택만 합산해 100점 수행률로 바꾸고, 원칙별 점수 평균을 에피소드 결과로 보여줍니다. 선택 이유와 근거, 사전·사후 변화, 개선 행동도 확인할 수 있습니다. 정부가 공식 점수를 제공한 것은 아니므로 루브릭 수준 배정의 타당성은 전문가 검토가 필요합니다. 현재 웹 유형은 규칙 기반으로 설명 가능하게 제공하고, K-means는 동의한 실제 기록이 충분히 모였을 때 유사 패턴을 탐색하기 위한 오프라인 분석 코드로 분리했습니다.

## 11. 예상 질문과 답변 요점

**정책을 가져오면 객관적인 점수가 되는 건가요?**

평가 축과 근거를 외부 기준에 연결해 설명 가능성을 높였습니다. 하지만 수준 배정과 수치 계산은 연구자가 설계했으므로 객관성과 타당성이 완전히 확보됐다는 주장은 하지 않습니다.

**왜 0~4단계이고 왜 같은 가중치인가요?**

행동의 위반, 위험, 부분 실천, 준수, 확장 실천을 구분하는 초기 교육용 설계입니다. 동일 가중치는 해석을 단순하게 하는 가정이며 전문가 검토와 민감도 분석으로 조정해야 합니다.

**AI가 채점하나요?**

아닙니다. 사전에 정의한 원칙별 루브릭이 채점하고, AI는 그 결과를 설명하거나 판단 이유 문구를 제공하는 역할입니다.

**K-means가 지금 어디서 실행되나요?**

별도 Python 오프라인 분석 스크립트에 있습니다. 현재 웹의 사용자 유형은 규칙 기반이고 학습된 K-means 추론과 연결되어 있지 않습니다.

**군집이 좋은 학생과 나쁜 학생을 가르나요?**

아닙니다. 유사한 선택 패턴과 취약 원칙에 맞춰 지도 활동을 제안하려는 탐색 분석입니다. 인격이나 능력의 등급을 붙이기 위한 모델이 아닙니다.

**학습 효과가 검증됐나요?**

계산과 기능 테스트는 수행했지만, 그것만으로 학습 효과가 검증되지는 않습니다. 실제 학습자 연구와 전문가 검토를 별도로 해야 합니다.

**개인정보와 동의는 어떻게 다루나요?**

연구 활용 동의를 기록하고 교수자에게는 집계 통계를 제공합니다. 모델 입력 파일의 식별 정보 제거, 중복 처리, 동의 철회 대응 등 운영 절차는 추가로 검증해야 합니다.
